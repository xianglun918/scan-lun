# ADR-0004：调度语义——每日单次、不补发、仅工作日、snooze、已答不重弹

- 状态：已接受
- 日期：2026-08-22

## 背景

定时提醒是核心。需要定义：触发频率、错过后的行为、周末是否提醒、稍后提醒、以及「填过就不打扰」的语义。

## 决策

- **每日单次**：读 `trigger_time`，算到下一个触发点的 `Duration` 并 sleep；循环调度。改动设置后经 `SchedulerMsg::Reload` 通知立即重算（mpsc channel）。
- **不补发**：启动/改设置时若当日触发点已过，直接目标明日，绝不补发（避免开机或午后设 9:00 时立刻弹出打扰）。
- **仅工作日**：到点时若 `workdays_only` 开启且是周六/周日，则跳过（不 emit）。
- **snooze（稍后提醒）**：`snooze_reminder(mins)` 后台 spawn 一个 `sleep(mins)` 后重发提醒事件；前端固定 60 分钟。
- **已答不重弹**：emit 前查 `today_answered()`，今日已有保存记录则不 emit。此为后端守卫；UI 侧（prompt 打开时已答）的提示态在 Phase 3 落实。

## 理由

- 「不补发」避免任何迟到打扰，契合极简定位；「已答不重弹」避免用户保存后又被打扰。
- 调度用 tokio `select!`（sleep vs channel）单一循环，Reload 即时生效，避免反复重建 timer。

## 后果

- 一天最多一个提醒时机；snooze 会重发但调度器守卫仍生效（当日已答则不弹）。
- `parse_time` 对非法时间字符串容错回退到 18:00，且 clamp 到 00:00–23:59。
